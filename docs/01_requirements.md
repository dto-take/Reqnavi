## 1. お客様概要

社内サービスであり、外部顧客は存在しない。対象組織：自社SIer事業部門（SE/PM）。対象ユーザー：案件担当SE（顧客が直接操作することはない）。新規案件から適用し、進行中案件への適用は行わない。

## 2. プロジェクトの目的

- **背景**：要件定義工程の属人化、確定後の仕様ブレ・追加見積りの発生
- **目的**：AI活用型要件定義支援サービス「ReqNavi」により、素案生成・認識合わせ・確定判定によるブレ防止を実現
- **留意事項**：AIの出力は候補提示に留め、最終確定は必ずSEが行う。顧客は直接操作しない

## 3. ロードマップ

| Phase | 主眼 | 主な内容 |
|---|---|---|
| Phase 0 | 土台・計測準備 | 認証・組織/案件構造・RLS基本設計、工数ベースライン実測 |
| Phase 1（MVP） | 素案生成×汎用テーブル | 資料格納・分類、AI素案生成、汎用構造化テーブルエディタ、辞書ベース曖昧検出、ドキュメント出力 |
| Phase 2 | 認識合わせの強化 | 業務フローエディタ、画面ワイヤーフレーム・遷移図、進捗ガント、AI曖昧判定 |
| Phase 3 | 確定判定ゲート | 充足率ダッシュボード、例外承認、整合性チェック、ベースライン確定・差分管理 |
| Phase 4 | 組織階層・案件横断連携 | 同一顧客内の他案件参照、案件間整合性チェック |
| Phase 5 | 社内展開・効果検証 | 本格運用、KPI実績検証、プロンプト改善 |

## 4. KPI

**要件定義工数 40% 削減**。導入前後の実工数を計測して検証する（導入前：直近案件の実測、導入後：ReqNavi上の作業時間記録）。

## 5. システム要件

- Next.js 15 (App Router) + Supabase (BaaS) + Vercel + AI API（Edge Functions/Server Actions経由）
- 学習に利用しないことが確認できるAI APIを前提（法務確認要）
- 案件（project_id）単位のRLSデータ分離
- 認証はPM Vision準拠（詳細は02_architecture.md参照）

## 6. 開発スコープ

**Phase 1対象**：資料格納・簡易分類／AI素案生成（Flow1）／汎用構造化テーブルエディタ／ステータス管理／曖昧表現検出（辞書）／ドキュメント出力／工数記録／Salesforce標準機能マッピング（プラットフォーム知識セット）

**Phase1対象外**：業務フロー・画面エディタ／進捗ガント／確定判定ゲート・ベースライン管理／組織横断連携

**恒久的対象外**：顧客セルフ操作／リアルタイム音声認識／進行中案件への適用

**プラットフォーム方針**：対象案件がSalesforce導入案件に集中しているため、Phase1はSalesforce特化でAI素案生成の精度を最大化する。ただしプラットフォーム知識（標準機能マッピング）はコードから分離し（`platform_knowledge_sets`）、将来他プラットフォームへの対応も可能な設計とする。

## 7. ビジネス要件

要件確定判定ゲートとベースライン管理により、確定後の仕様変更・追加見積りを防止し、本サービスの中核価値とする。曖昧表現の自動検出により若手SEの品質を底上げする。

## 8. 業務要件

資料格納 → AI素案生成 → リファインメント（直接入力／議事録反映）→ 整合性チェック → 確定判定ゲート → ベースライン確定 → ドキュメント出力。確定後の変更は差分（変更申請）として記録する。

### 9.1 画面ナビゲーションの考え方

15章を標準プロセス順に並べたステッパーを常設するが、編集自体はロックしない。章をまたぐ参照には根拠・影響先のリンクチップを表示し、標準順＋依存関係マップから「次にやるべきこと」を控えめに提示する。全体進捗は確定判定ダッシュボードの集計値をヘッダーに表示する。

## 10. 非機能要件

| 分類 | 概要 |
|---|---|
| 可用性 | Vercel + Supabase 標準SLA準拠 |
| 性能 | 打合せ同席モードの即応性（SSR/ISR + Realtime差分反映） |
| セキュリティ（データ分離） | RLSによるproject_id単位分離 |
| セキュリティ（AI利用） | 学習未使用API契約が前提 |
| セキュリティ（認証・権限） | PM Vision準拠。パートナーはコスト情報・組織横断データへのアクセス不可、Google OAuth不可 |
| 監査性 | item_history／baseline_snapshotsで追跡 |
| 移植性 | 既存社内アーキ（PM Vision）と同一スタック |

## 11. データ移行要件

対象外。新規案件からの適用のみ。

## 12. トレーニング要件

Phase1リリース時に対象SE・PMへ利用方法の説明会を実施。

## 13. システム運用要件

監視・プロンプト改善・バックアップ確認を実施。**運用担当部門は未確定（Phase1リリースまでに決定要）**。

## 14. システム定着化支援要件

Phase5以降、月次でのKPI進捗共有、SEフィードバック収集、活用事例の展開を行う。

## 15. 進捗

Phase0〜5の順で進行。開発着手後はステップごとの指示書に基づき別途進捗管理する。
