# 指示書：業務フロービルダー フェーズD（ノードパレット・挿入位置ルール・視覚的な仕上げ）

## 目的

1. 左サイドバー（またはそれに相当するUI）にノード種別のパレットを設置し、クリック/ドラッグで新規ノードを挿入できるようにする
2. 挿入位置のルール（選択中ノードの後に挿入する、条件分岐削除時のYes/Noルートの扱い等）を実装する
3. 暫定実装だった「+ 本線の末尾に工程を追加」ボタンをパレットに置き換える
4. 視覚的な仕上げ（ホバー状態・空状態・ドラッグプレビュー等）を行う

## 重要な前提：詳細仕様は自分で一次情報を確認すること

**パレットの構成・挿入位置の正確なルール（特に条件分岐ノードの削除時の挙動、本線とYes/Noルートの接続関係の維持方法）は、この指示書の記憶に頼った要約ではなく、`design_handoff_workflow_builder/README.md`の該当節、および`workflow-requirements-builder.dc.html`の実際の挙動を直接確認してから実装すること。** 本指示書は実装の大枠のみを示す。

## 前提確認

- 業務フロービルダー フェーズC（ユースケース記述・業務手順表・CSV出力）が完了していること
- デザインハンドオフ一式（`design_handoff_workflow_builder/`）が手元にあること

---

## Step 1: デザインハンドオフの該当節を確認

着手前に、以下を実際に読み込み、要点をメモしてから次に進むこと。

1. `README.md`の「ノードパレット」「挿入位置」「工程の追加・削除ルール」に相当する節
2. `workflow-requirements-builder.dc.html`を開き、パレットからのノード追加・条件分岐ノードの削除の実際の挙動を目視で確認する

## Step 2: ノードパレットUIを作成

新規ファイル `src/components/domain/workflow-builder/NodePalette.tsx`。

- ノード種別（開始/手動タスク/承認/条件分岐/自動通知/自動処理/終了）を、Step1で確認した構成・アイコン・色（フェーズAで既に移植済みのノード種別マスタと同じ配色を再利用する）でボタン一覧表示する
- クリックで「選択中のノードの直後に、その種別のノードを挿入する」動作とする（Step1で確認したドラッグ&ドロップの詳細仕様が実装コストに見合わない場合、クリック挿入のみでも良いと判断してよいが、その場合は理由をコメントに残すこと）
- 何も選択されていない状態でパレットをクリックした場合の挙動も、Step1の確認内容に従う

## Step 3: 挿入ロジックをServer Actionとして実装

`src/actions/workflow-builder.ts`に、選択中ノードの直後に新規ノードを挿入する関数を追加する。

```ts
export async function insertWorkflowNodeAfter(
  projectId: string,
  tenantId: string,
  afterNodeId: string | null,
  nodeType: string
) {
  // Step1で確認した仕様に従い、以下を実装する：
  // 1. afterNodeIdがnullの場合は本線末尾に追加（既存のappendWorkflowNodeと同等の動作）
  // 2. afterNodeIdが指定されている場合、そのノードの直後に割り込む形で挿入する
  //    （同じbranch・parent_condition_id内で、afterNodeIdより後ろのorder_indexを
  //    1つずつ繰り下げてから、afterNodeIdのorder_index+1に新規ノードを挿入する）
  // 3. 挿入するノードの種別がconditionの場合、Yes/Noそれぞれに空のブランチを作る
  //    （実際にステップを持たない状態＝スタブ表示になることは既にフェーズAで対応済みのため、
  //    ここでは条件ノード自体の作成のみでよい）
}
```

**注意**：既存ノードの`order_index`繰り下げは複数行のUPDATEが必要になる。`flow_nodes`へのUPDATE用RLSポリシーが既に整備されているか確認すること（規約12・16）。

## Step 4: 条件分岐ノードの削除ルールを実装

条件分岐ノード削除専用の処理を追加する（通常ノードの削除は既存のシンプルな削除のままでよい）。

Step1で確認した実際の挙動に従って実装する。**削除は復元不可能な操作のため、通常ノードの削除確認とは別に、条件分岐ノードを削除する場合は「Yes/Noそれぞれの配下に◯件のステップがあります。削除するとどうなるか」を明示した確認ダイアログを表示すること。**

## Step 5: 暫定ボタンの置き換え・視覚的な仕上げ

`instructions_workflow_builder_minimal_add.md`で追加した「+ 本線の末尾に工程を追加」ボタンを、`NodePalette`に置き換える（暫定実装のコードは削除する）。

Step1で確認した視覚的な詳細（ホバー時の見た目、パレットボタンの配置・余白、選択中ノードのハイライトとパレットの連動等）を反映する。この部分の具体的な数値・微調整はお任せする。

## Step 6: 動作確認

1. ノードが0件の状態から、パレットの「開始」をクリックし、開始ノードが作成されることを確認する
2. 続けて「手動タスク」を数回クリックし、直前に選択していたノードの直後に正しく挿入されることを確認する（末尾ではなく、途中への挿入も試す）
3. 「条件分岐」を挿入し、Yes/No両方のスタブが表示されることを確認する
4. Yes側・No側それぞれにステップを追加し、フロー図・業務手順表・ユースケース記述の全てに反映されることを確認する（フェーズCとの整合性）
5. 条件分岐ノードを削除し、確認ダイアログの内容通りの挙動になることを確認する
6. 暫定の「+ 本線の末尾に工程を追加」ボタンが無くなっていることを確認する

## やってはいけないこと

- Step1の確認を省略し、記憶やこの指示書の要約だけを頼りに実装しない
- 条件分岐ノードの削除で、配下のステップ数が分からないまま削除を実行できる状態にしない
