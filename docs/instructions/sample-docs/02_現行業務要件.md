# 現行業務要件（As-Is）：営業プロセス

## 1. 現状の業務フロー概要

営業部における現状の商談プロセスは、概ね以下の流れで行われている。

1. **見込み客登録**：営業担当者が展示会・Webサイトからの問い合わせを受け、Excel台帳「見込み客リスト.xlsx」に手入力で登録する
2. **初回商談**：営業担当者が訪問・オンライン会議を実施し、Excelの商談メモに記録する
3. **見積作成**：営業担当者がWordの見積書テンプレートを個別にコピーして作成し、金額・条件を入力する。テンプレートは部署内で統一されておらず、担当者ごとに微妙に異なるバージョンを使っている
4. **見積承認**：金額が100万円以上の場合、営業マネージャーの承認が必要。承認は現状、見積書を印刷して押印する運用と、メールで「承認します」と返信する運用が混在している
5. **受注登録**：受注が確定した商談について、営業担当者が別のExcel台帳「受注管理台帳.xlsx」に手入力で転記する
6. **契約情報の基幹システムへの反映**：受注情報を、情報システム部門の担当者が月次でまとめて既存の基幹システム（会計システム）に手入力する

## 2. 現状の課題

- 見込み客リストと受注管理台帳が別ファイルのため、同一顧客の情報が重複・不整合を起こすことがある
- 見積書の承認プロセスが担当者によって運用が異なり、承認の記録が残らないケースがある
- 基幹システムへの反映が月次のため、リアルタイムの売上状況が経営層に見えない
- 営業マネージャーが商談の進捗状況を把握する手段が、週次の会議での口頭報告に限られている

## 3. 現状の担当者・システムの対応関係

| 業務 | 担当者 | 使用システム・ツール |
|---|---|---|
| 見込み客登録 | 営業担当者 | Excel（見込み客リスト.xlsx） |
| 初回商談記録 | 営業担当者 | Excel（商談メモ） |
| 見積作成 | 営業担当者 | Word（見積書テンプレート、担当者ごとに差異あり） |
| 見積承認 | 営業マネージャー | 紙押印 または メール返信（運用が統一されていない） |
| 受注登録 | 営業担当者 | Excel（受注管理台帳.xlsx） |
| 基幹システムへの反映 | 情報システム部門担当者 | 既存基幹システム（会計システム） |

## 4. 補足

上記のフローは東京本社の運用を基準に記載しているが、大阪支社では見積書テンプレートが東京本社と異なるバージョンを使用しており、細部の運用は拠点によって柔軟に対応している部分がある。
