# システム要件・ビジネス要件

## 1. システム要件

### 1.1 既存システムとの連携
既存の基幹システム（会計システム、△△システム社製）との間で、顧客情報（会社名・部署・担当者名・住所）を連携する必要がある。連携方式は既存基幹システム側がREST APIを提供していないため、現時点ではCSVファイルによる連携を想定している。連携頻度は日次を想定しているが、詳細は基幹システム側の担当部門と別途調整する。

### 1.2 利用環境
- 営業担当者は外出先からモバイル端末（タブレット・スマートフォン）でシステムにアクセスする必要がある
- 東京本社・大阪支社の双方から、同一のデータをリアルタイムに参照できる必要がある

### 1.3 想定ユーザー数
営業担当者：約40名、営業マネージャー：約8名、情報システム部門：2名

## 2. ビジネス要件

### 2.1 課題と解決策

| 課題・要望 | ソリューション | KPI |
|---|---|---|
| 商談状況が可視化されておらず、上長がリアルタイムに把握できない | Salesforce標準の商談（Opportunity）管理機能で一元化 | 商談報告のための会議時間を50%削減 |
| 見積書のフォーマットが担当者ごとに異なり、承認記録が残らない | Salesforce標準の見積（Quote）機能と承認プロセス（Approval Process）を導入 | 見積承認のリードタイムを3日から1日に短縮 |
| 顧客情報が営業部と基幹システムで分断されている | 顧客情報を日次でCSV連携し、常に最新化する | データ不整合件数を月間0件にする |
| 経営層への売上報告が月次かつ手作業 | ダッシュボード機能によるリアルタイム売上可視化 | 売上報告の作成時間を月4時間から30分に短縮 |

### 2.2 その他のビジネス要望

- 将来的には大阪支社以外の拠点（名古屋・福岡）にも展開する可能性があるため、拠点追加が柔軟に行える設計を希望する
- 経営層は、四半期ごとの売上予測の精度向上を特に重視している
