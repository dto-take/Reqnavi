# 指示書：画面遷移図UX改善 フェーズ1（データモデル拡張・キャンバス描画・右パネル・9章紐付け）

## 目的

添付のデザインハンドオフ（`design_handoff_screen_flow/README.md`）の採用案7aに基づき、9章の画面遷移図（`/projects/[id]/chapters/9/screen-transitions`）を、現状の「小さな固定高の図＋追加フォーム＋削除リスト」の3分割構成から、**キャンバス（主役）＋右パネル**の構成に置き換える。

**本フェーズの対象**：データモデル拡張、キャンバス描画（ノード・エッジのルーティング・往復オフセット）、ノードのドラッグ移動と位置の保存、右パネル3モード、画面の追加/名前変更/削除、遷移の追加（右パネルから）/操作名編集/削除、9章との紐付けと警告表示。

**対象外**：ポートからのドラッグによる遷移作成・自動で整列・ズーム・確定ワークフロー（フェーズ2）、AI素案の差分提案（フェーズ3）、キーボード操作・パン・ロールバック等の仕上げ（フェーズ4）。

## 重要な方針

### デザイントークン
ReqNaviの既存デザインシステム（深緑系ブランドカラー・Inter一本化）を優先する。緑＝primary/確定、琥珀＝要確認、赤茶＝削除・孤立、破線＝AI由来という**役割**は踏襲し、実際の値は既存トークンにマップする。新しい書体（Shippori Mincho・Zen Kaku Gothic New・IBM Plex Mono）は追加しない。

### 描画ライブラリ
React Flow等の新しい依存は追加しない。業務フロービルダー（`SwimlaneCanvas.tsx`）で確立済みの自前SVG描画の考え方を踏襲する。エッジのルーティング仕様は、README本文の要約よりも**HTMLファイル内の`geom()`関数の実際の実装を一次情報として**移植すること。

### ステータスの語彙
`flow_nodes`に追加するステータスは、新しい語彙（draft/review/confirmed）を作らず、`requirement_items`と同じ値（`ai_draft`/`se_reviewing`/`confirmed`）を使う。これにより既存の`isItemLocked`をそのまま再利用できる（確定ワークフロー自体はフェーズ2で実装する。本フェーズでは状態ドットの表示のみ）。

## 前提確認

- ハンドオフの`画面遷移図 7a 高精度デザイン.dc.html`を実際にブラウザで開き、ノードのドラッグ・エッジの描画（特に往復ペアのオフセット）・右パネルの3モードの切り替わりを目視で確認してから着手すること
- 現在の`flow_nodes`・`flow_edges`の実際のスキーマ、`flow_edges`の外部キーのON DELETE挙動、`flow_nodes`のUPDATE用RLSポリシーの有無を確認すること（規約47：RLSで弾かれたUPDATEはエラーにならず0件更新になる）

---

## Step 1: データモデルを拡張する

マイグレーションを作成し、`flow_nodes`に以下を追加する（`flow_type='screen_transition'`で使用。他のflow_typeには影響させない）。

- `pos_x` / `pos_y`（numeric、キャンバス上の座標）
- `function_item_id`（uuid、`requirement_items(id)`への外部キー、`ON DELETE SET NULL`。9章項目が削除されたらノードは未紐付けに戻る）
- `screen_code`（text、`S-01`形式の画面ID。表示用）
- `status`（text、`ai_draft`/`se_reviewing`/`confirmed`、既定値`se_reviewing`）

制約：
- 1つの9章項目は1ノードにのみ紐付く：`(project_id, function_item_id)`の部分一意インデックス（`function_item_id is not null`かつ`flow_type='screen_transition'`の行に限定）

`flow_edges`について：
- 操作名を保持する`label`列が既に存在するか確認し、無ければ追加する
- `(from_node, to_node)`の一意制約を追加する。**追加前に既存データの重複を確認し、重複があれば1件に統合してから制約を張ること**
- 自己ループ（`from_node = to_node`）を禁止するCHECK制約を追加する

### 既存データの移行（同じマイグレーション内で行う）
1. **9章項目への自動紐付け**：既存の画面ノードのうち、ノード名（`label`）が9章の画面情報を持つ項目の`content.name`と**完全一致**するものを紐付ける。ただし、同名の9章項目が複数ある・同名のノードが複数あるなど**一意に対応しない場合は紐付けずに未紐付けのまま残す**（部分一意インデックスに違反させない）
2. **座標の初期値**：既存ノードの`order_index`順に、格子状（横270px間隔・縦120px間隔の目安）に配置する初期座標を設定する
3. **画面ID**：既存ノードに`order_index`順で`S-01`、`S-02`…を振る

**注意**：移行ロジックは、本番適用前にローカルで実データ相当のテストデータ（同名重複・未一致・既に重複したエッジを含む）を作って検証すること（非機能要件フェーズ1で重複データを移行した際と同じ手順）。

## Step 2: 派生値の計算ロジックを作成する

新規ファイル`src/lib/screen-flow/derive.ts`（通常モジュール、DBに依存しない純粋関数）に以下を実装する。

- 各ノードの入次数・出次数
- 警告一覧：9章未紐付け／入出遷移がともに0（孤立）。1ノードに両方該当する場合は理由を連結する
- 「9章にあって図にない画面」：9章の画面情報を持つ項目（`content.screen_fields`が空でないもの。既存の「画面イメージ」ページと同じ判定条件を共有すること）のうち、`status = 'rejected'`を除き、どのノードにも紐付いていないもの
- エッジのパス・矢頭・ラベル座標（`geom()`の移植）。往復ペア（A→BとB→Aが両方ある）の判定とオフセットを含む

## Step 3: キャンバスを実装する

新規ディレクトリ`src/components/domain/screen-flow/`に、オーケストレータ（`ScreenFlowScreen.tsx`）・キャンバス（`ScreenFlowCanvas.tsx`）・右パネル（`ScreenFlowPanel.tsx`）を作成する（業務フロー・KPI・非機能要件と同じ3ファイル構成）。

- 2カラム構成（キャンバス＋右パネル）。ハンドオフの56pxアイコンレールは、既存の章サイドバーがあるため採用しない
- ドットグリッドの背景、論理サイズのステージ（本フェーズでは等倍固定、ズームはフェーズ2）
- 画面ノード：状態ドット・画面ID・AI提案タグ枠（本フェーズでは未使用）・「⚠ 孤立」タグ・画面名（1行省略）・9章紐付け表示（未紐付けは琥珀）
- 接続ポート（●）は**表示のみ**（ドラッグでの遷移作成はフェーズ2）
- エッジ：三次ベジェ＋矢頭、通常/選択中の画面に関わる線/選択中の遷移の3段階の強調、ラベルはノードより前面
- クリック判定用の透明な太線
- 背景クリックで選択解除

### ノードのドラッグ移動
- 3px未満の移動はクリック（選択）とみなす
- ステージ内にクランプする
- ドラッグ中はローカル状態で描画し、ドラッグ終了時に座標を保存する
- **保存直後にサーバーの再取得データが届くまでの間、ノードが元の位置に一瞬戻らないようにすること**（規約59：上書き値は実データが追いつくまで消さない）

## Step 4: 右パネルの3モードを実装する

### 未選択時（全体の確認）
- 要確認リスト（クリックでその画面を選択）。問題が無ければ「問題はありません。」
- 「9章にあって図にない画面」リスト＋「図に追加」（その9章項目に紐付いたノードを作成し、選択状態にする）

### 画面ノード選択時
- 画面ID・ステータスピル
- 画面名（クリックで編集）
- 9章の画面情報
  - 紐付け済み：機能名・**画面イメージ**（既存の「画面イメージ」ページで使っているプレビューコンポーネントを**再利用**すること。新しく描画を作らない）・「画面イメージを開く」・「紐付けを外す」
  - 未紐付け：琥珀カードに案内文＋未使用の9章画面の候補リスト（クリックで紐付け）
- 遷移先一覧（「並列に存在できます」）：行クリックでその遷移を選択、`×`で削除。「＋ 遷移先を追加」で、まだ遷移先になっていない画面をチップで表示し、クリックで追加
- 遷移元一覧：0件なら「なし（起点の画面として扱います）」
- アクションバー：「画面を削除」（確認ダイアログ付き。接続する遷移も削除される旨を表示する）。「この画面を確定」はフェーズ2で追加する

### 遷移選択時
- 遷移元画面 → 遷移先画面（各ボタンでその画面を選択）
- 遷移のきっかけ（操作名）：クリックで編集
- 「戻りの遷移を追加」（逆向きの遷移が無いときのみ表示）・「遷移を削除」

**注意**：遷移元・遷移先・操作名など、ドラッグ以外の経路（他のノードの削除、紐付けの変更等）で外部から値が変わりうる入力欄は、`key`にidだけでなく値も含めること（規約58）。

## Step 5: Server Actionを実装・整理する

`src/actions/`に、以下を実装する（既存の画面遷移関連のアクションがあれば、そこに統合する）。

- `moveScreenNode(nodeId, x, y)`
- `addScreenNode(projectId, { name, functionItemId? })`：画面IDを採番して作成
- `renameScreenNode` / `removeScreenNode`（接続する遷移も削除。外部キーの実際の挙動を確認し、カスケードで消えない場合は明示的に削除する）
- `linkScreenFunction(nodeId, functionItemId | null)`：既に他ノードで使用されている9章項目は紐付けを拒否する
- `addScreenTransition(from, to, label?)`：自己ループ・同方向の重複は作らない
- `updateScreenTransitionLabel` / `removeScreenTransition`

エラーは`UserFacingError`＋`errorMessage()`で返す（規約43）。

### 既存のAI一括生成について
既存の`generateScreenTransitionDraft`（ノード0件時のみ実行可能な一括生成）は、フェーズ3で差分提案に置き換えるまで**残してよい**。ただし、作成するノードに本フェーズで追加した列（座標・画面ID・`function_item_id`）を正しく設定するよう修正すること。このアクションは元々9章の画面情報を持つ項目から画面名を作っているため、`function_item_id`も同時に設定できるはずである。

## Step 6: 旧UIを撤去する

現状の追加フォーム（画面名入力＋「画面追加」、遷移元/遷移先セレクト＋遷移条件＋「追加」）と、削除リストを撤去する。撤去前に、それらが呼んでいたServer Actionの呼び出し箇所をgrepで確認し、他から使われていなければ不要なものを削除すること（規約36）。

## Step 7: 動作確認

1. 画面遷移図を開き、キャンバス＋右パネルの構成で表示されることを確認する
2. 既存データ：名前が完全一致するノードは9章項目に紐付いていること、一意に対応しないものは未紐付けのまま残っていることをDBで確認する
3. ノードをドラッグで移動し、リロード後も位置が保持されることを確認する。ドロップ直後に元の位置へ一瞬戻らないことも確認する
4. 往復の遷移（A→BとB→A）を作り、線とラベルが重ならないことを確認する
5. 右パネルの3モード（未選択・画面ノード・遷移）が選択対象に応じて切り替わることを確認する
6. 「9章にあって図にない画面」から「図に追加」し、紐付け済みのノードが作成・選択されることを確認する
7. 紐付けの解除・別の9章項目への紐付け直しができ、既に使用済みの9章項目は候補から除外されることを確認する
8. 遷移先の追加・操作名の編集・遷移の削除・「戻りの遷移を追加」が機能することを確認する
9. 画面を削除すると、接続する遷移も削除されることを確認する
10. 未紐付け・孤立のノードが要確認リストに表示され、ノード上にもタグが出ることを確認する
11. 既存のAI一括生成（ノード0件時）で作成されたノードに、座標・画面ID・紐付けが設定されることを確認する

## やってはいけないこと

- React Flow等の新しいグラフ描画ライブラリを追加しない
- 新しい書体を追加しない
- ステータスに新しい語彙を作らない（`requirement_items`と同じ値を使う）
- 名前が一意に対応しない既存ノードを、推測で9章項目に紐付けない
- 9章の画面イメージのプレビューを、新しく描画し直さない（既存コンポーネントを再利用する）
- ポートドラッグでの遷移作成・自動整列・ズーム・確定ワークフロー・AI差分提案を本フェーズで実装しない
