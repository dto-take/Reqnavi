# 指示書：画面遷移図UX改善 フェーズ4（キーボード操作・ホイールズーム・パン・失敗時ロールバックの総点検・視覚仕上げ）

## 目的

画面遷移図の最終フェーズとして、次の4点を行う。

1. キーボード操作（`Delete`/`Backspace`で削除、`Esc`で接続キャンセル／選択解除、矢印キーでノード移動）
2. `Ctrl`/`⌘`+ホイールでのズーム、`Space`を押しながらのドラッグでのパン
3. **各操作の失敗時の挙動の総点検**（楽観的に画面を更新している操作は、失敗時に元へ戻す）
4. 視覚仕上げ（フォーカスリング・カーソル・操作ヒント・空状態・狭い画面幅）と、ヘルプ・使い方パネルへの追記

**マイグレーションとGemini呼び出しは不要**（検証でも使わない）。

## 重要な設計判断

### キー操作の対象と、取り扱いの規則
| キー | 動作 |
|---|---|
| `Delete`／`Backspace` | 選択中の対象を削除。**Macの「delete」キーは`Backspace`を発するため、両方を受け付ける** |
| `Esc` | 優先順位：①接続ドラッグ中ならキャンセル → ②選択を解除 |
| 矢印キー | 選択中の**実ノード**を1px移動（`Shift`で10px） |
| `Space`（押している間） | パンモード（ドラッグでキャンバスをスクロール） |
| `Ctrl`/`⌘`+ホイール | ズーム |

- **`Tab`／`Shift+Tab`は奪わない**（ブラウザ標準のフォーカス移動を維持する。KPI画面フェーズ4と同じ方針）
- `Delete`の対象ごとの挙動は、**右パネルの該当ボタンと同じ処理を呼ぶ**（確認ダイアログの有無・確定済みの扱いを含む）。キー専用の別実装は作らない
  - 実ノード：「画面を削除」と同じ（確定済みなら「確定済みの画面です」、接続する遷移も削除される旨の確認）
  - 実遷移：「遷移を削除」と同じ。遷移元が確定済みで削除できない場合は、何もせず「確定済みの画面からの遷移は削除できません」とトースト表示する
  - 提案（ノード・遷移）：「見送り」と同じ
- テキスト入力欄・セレクト・ボタンにフォーカスがある間は、これらのキーを**一切横取りしない**（`INPUT`/`TEXTAREA`/`SELECT`/`BUTTON`、`contenteditable`）
- **配置はロックの対象外**（フェーズ2の方針）。確定済みノードも矢印キーで動かせる。提案ノードは動かせない

### 既知の制約として残すもの
ノード・遷移は`Tab`での移動対象にしない（ハンドオフの設計どおり、選択はクリックか、右パネルの一覧からの選択）。キーボードのみでノードを選択する手段は、右パネルの「要確認」リストと遷移先・遷移元の行に限られる。完全なキーボードのみの操作は本フェーズの対象外とする。

## Step 1: キャンバスをキーボード操作の対象にする

- キャンバスのスクロールコンテナを`tabIndex={0}`にし、ノード・背景・遷移のポインタ操作でこのコンテナにフォーカスを移す（`focus({ preventScroll: true })`）。キー入力は**このコンテナの`onKeyDown`で受ける**（`window`への常駐リスナーは使わない）
- キーボードでフォーカスが入ったときだけ視認できるフォーカスリング（`focus-visible`）を付ける。マウス操作で選択した直後に大きな枠が出ないこと

## Step 2: 削除・Esc・矢印キーを実装する

**削除**：上記の規則どおり。削除後は選択を解除し、キャンバスのフォーカスは維持する

**Esc**：接続ドラッグ中ならキャンセルして破線を消す。そうでなければ選択解除

**矢印キーによるノード移動**
- 選択中の実ノードを、押すたびに論理座標で1px（`Shift`で10px）移動する。ステージ内にクランプする（現在のステージ寸法を使う。規約61）
- 表示は即座に反映する（上書き値）。**サーバーへの保存はキー入力ごとに行わず、最後の入力から約400ms後にまとめて1回行う**（キーを押し続けた場合の大量リクエストを避ける）
- 選択の切り替え・`Esc`・ページ遷移・コンテナのフォーカス喪失の際は、保留中の保存を**即時に実行**してから進める（保存されないまま消えない）
- 保存に失敗した場合は、上書きを外して元の位置へ戻し、エラートーストを表示する（Step 5の総点検の一部）
- 矢印キーがキャンバスのスクロールを動かさないよう、選択中のノードがあるときは`preventDefault`する

## Step 3: `Ctrl`/`⌘`+ホイールズームを実装する

- **`wheel`イベントは、`addEventListener('wheel', handler, { passive: false })`でネイティブに登録する**。Reactの`onWheel`は受動リスナーとして登録されるため`preventDefault()`が効かず、ブラウザ全体のズームが同時に走ってしまう
- `ctrlKey`または`metaKey`が付いたホイールのときだけズームする。付いていない通常のスクロール（トラックパッドの2本指スクロール含む）は妨げない
- 倍率は連続的に変える（例：`scale × exp(−deltaY × 0.0015)`を50〜160%にクランプ。表示は整数%に丸める）。ツールバーの`−`/`＋`は従来どおり0.1刻み
- **ホイールズームはカーソル位置を基準に拡縮する**（カーソルの下の論理座標が動かないよう、倍率の更新後にスクロール位置を補正する）。ツールバー操作は表示領域の中央を基準にする。補正は`useLayoutEffect`内でスクロール量を設定する形でよい（`setState`を伴わないため、規約54のリントには抵触しない）
- 座標変換はフェーズ2の共用関数を使う（規約61）

## Step 4: `Space`+ドラッグのパンを実装する

- `Space`を押している間、キャンバスのカーソルを`grab`、ドラッグ中は`grabbing`にし、ポインタの移動量だけコンテナの`scrollLeft`/`scrollTop`を動かす
- **パンモード中に押したポインタは、ノードのドラッグ・選択・背景クリックによる選択解除・ポートの接続のいずれも開始させない**（ノードの上で`Space`+ドラッグを始めても、ノードは動かない）
- `Space`のスクロール動作（ページ送り）は、キャンバスにフォーカスがあるとき`preventDefault`する。キーの自動連打（`repeat`）は無視する
- `keyup`、およびコンテナの`blur`・ウィンドウの`blur`でパンモードを必ず解除する（押しっぱなしの状態が残らないこと）

## Step 5: 失敗時の挙動の総点検

画面遷移図のすべての更新操作について、実装を実際に読み、次の基準で整理・修正する。**結果を表にして報告すること**（操作／楽観的更新の有無／失敗時の挙動）。

| 操作の種類 | 基準 |
|---|---|
| ノードのドラッグ移動、矢印キー移動、自動で整列（楽観的に表示する） | 失敗時に上書きを外して元の位置に戻し、エラートースト、再取得で表示をDBの実際の状態に揃える |
| 画面名・操作名のテキスト編集（保存する） | 失敗時にエラートーストを出し、**入力欄を最後に保存できた値へ戻す**（保存されていない値が画面に残り続けない） |
| 確定、9章紐付けの変更・解除、遷移の追加・削除、画面の追加・削除、提案の採用・見送り（サーバーの応答後に画面が変わる） | 失敗時はエラートーストのみ。画面は変えない。操作中はボタンを無効化して連打を防ぐ |

- ポインタイベントやキーイベントから直接呼ぶ操作は、`error.tsx`に例外が届かないため、**必ず`try/catch`でトースト表示する**（規約44）。呼び出し箇所をgrepで洗い出し、漏れが無いことを確認する
- サーバーが「確定済みのため拒否」のようにロール状態の食い違いを理由に失敗した場合は、トースト表示のあと、**再取得して画面をDBの実際の状態に揃える**
- 失敗の再現は、Server Actionへの`Next-Action`ヘッダ付きPOSTを中断する方法（進捗画面フェーズ4で用いたもの）で行う

## Step 6: 視覚仕上げ

- フォーカスリング：ヘッダーのボタン、ズームツールバー、右パネルのボタン・チップ・選択行、AI提案バーのボタンで、キーボードフォーカス時に視認できるリングが出ること。足りない箇所だけ追加する（共通の`Input`/`Select`等は既に対応済み）。ズームツールバーのボタンには`aria-label`（縮小／拡大／100%に戻す）を付ける
- カーソル：ノードは`grab`／ドラッグ中`grabbing`、ポートは`crosshair`、接続ドラッグ中はキャンバス全体を`crosshair`。ドラッグ・パン中はテキスト選択が起きないこと
- 操作ヒント（ヘッダー右端）：「ドラッグで移動　●から遷移を作成　Space+ドラッグでパン　Ctrl/⌘+ホイールでズーム　Deleteで削除」のように、使えるキー操作を反映する。狭い幅では省略してよい
- 空状態：画面が0件のとき、キャンバスに案内を表示する（例：「画面がありません。『＋ 画面を追加』か『AI素案』から始めます」）。フェーズ1で既にあれば、文言が現状の機能と合っているか確認する
- 実データでの見た目の確認：6画面以上・往復遷移・並列遷移・提案が混在する図で、ラベル同士・ラベルとノードの重なり、選択時の強調、提案の破線の視認性が不自然でないか確認し、気になる点だけ軽微に調整する
- 狭い画面幅：1024px未満で、キャンバスと右パネルが縦積み（キャンバスが先、右パネルが後）になるなど、崩れない簡易対応を入れる（KPI画面フェーズ4と同様。細かい作り込みは不要）

## Step 7: ヘルプ・使い方パネルに追記する

`src/lib/help-content.ts`の`HELP_ENTRIES`に、画面遷移図のページ（`/projects/[id]/chapters/9/screen-transitions`）の概要を追加する。**既存のパターン`/chapters/\d+$`にはこのパスが一致しないため、専用のパターンを追加する**（パターンの並び順で、より具体的なものが先に評価されること）。概要には、画面と遷移の作り方、AI素案が差分で提案されること、確定すると編集できなくなること、キー操作（Delete・Esc・矢印・Space+ドラッグ・Ctrl/⌘+ホイール）を簡潔に書く。

## Step 8: 動作確認

実際のブラウザ・DBで確認する。**Geminiは使わない**（提案はDBに直接入れたデータで確認する）。

**キーボード**
1. 実ノードを選択して`Delete`、Macの`delete`相当の`Backspace`でも、ボタンと同じ確認ダイアログが出て削除できる。確定済みノードでは「確定済みの画面です」が出る
2. 実遷移を選択して`Delete`で削除できる。遷移元が確定済みの場合は削除されず、トーストが出る
3. 提案を選択して`Delete`で「見送り」になる
4. 接続ドラッグ中に`Esc`でキャンセルされ、破線が消える。ドラッグ中でなければ`Esc`で選択が解除される
5. 矢印キーで選択ノードが1px、`Shift`で10px動く。押し続けてもサーバーへのリクエストが連打されず、最後の入力の約400ms後に1回だけ保存され、リロード後も位置が一致する。ステージの端でクランプされる。確定済みノードも動く。提案ノードは動かない
6. 名前の入力欄・セレクト・ボタンにフォーカスがある間は、`Delete`・`Backspace`・矢印・`Space`がキャンバスの操作として働かない（入力欄で`Backspace`を押して文字が消えるだけで、ノードが削除されない）
7. `Tab`／`Shift+Tab`が通常のフォーカス移動として働く

**ズームとパン**
8. `Ctrl`（Macは`⌘`）+ホイールで、**ブラウザ全体のズームが起きず**、キャンバスだけが拡縮する。カーソルの下の位置が動かない。通常のホイールスクロールはこれまでどおり動く
9. 50%・100%・160%で、矢印キー移動・ドラッグ・ポート接続が引き続き正しい位置に働く
10. `Space`+ドラッグでキャンバスがスクロールする。**ノードの上から始めても、ノードが動かず、選択も変わらない**。`Space`を離す・ウィンドウからフォーカスが外れると、パンモードが解除される

**失敗時**
11. ノードのドラッグ、矢印キー移動、自動で整列のそれぞれで、Server Actionを中断すると、元の位置へ戻りエラートーストが出る
12. 画面名・操作名の保存を中断すると、エラートーストが出て、入力欄が最後に保存できた値へ戻る
13. 確定済みになった画面を、別経路で確定済みにした状態で古い画面から編集して拒否されたとき、トースト表示のあと表示がDBの実際の状態（確定済み）に揃う
14. Step 5の表が報告されており、ポインタ・キーから呼ぶすべての更新操作に`try/catch`があること

**視覚**
15. 各ボタンのフォーカスリング、カーソル、操作ヒント、空状態が反映されている。1024px未満・800pxで崩れない
16. ヘルプパネルで、画面遷移図のページを開くと専用の概要が表示される

**回帰**
17. フェーズ1〜3の機能（ドラッグ、ポートからの遷移作成、自動で整列、ズームツールバー、確定とロック、9章紐付けの変更・解除、画面の追加、警告表示、AI提案の採用・見送り・一括操作）に回帰が無いことを確認する

## やってはいけないこと

- `Tab`／`Shift+Tab`をブラウザ標準のフォーカス移動から奪うこと
- 入力欄にフォーカスがある間にキー入力を横取りすること
- `wheel`をReactの`onWheel`で処理すること（`preventDefault`が効かない）
- 矢印キー1回ごとにServer Actionを呼ぶこと（保存はまとめて行う）
- ロックされた確定済みノードの位置移動を禁止すること（配置はロックの対象外）
- 失敗時の挙動を、画面ごとに別々の流儀で実装すること（Step 5の基準に揃える）
- 新しい依存ライブラリを追加すること
