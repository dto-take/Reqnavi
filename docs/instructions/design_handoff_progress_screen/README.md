# Handoff: 「15. 進捗」画面（大／中工程のWBS＋簡易ガント）のUX改善 — 案 5c

## Overview

ReqNavi（案件の要件定義を15章立てで作成・レビューするWebアプリ）の **15. 進捗 章ページ** の改修デザイン。

この章の目的は**実績進捗の管理ではなく、要件定義の段階で「今後の進め方」を工程として定義すること**。したがって本設計では **進捗率・完了・締切・遅延の概念を持たない**。扱うのは「大工程／中工程の階層」「期間」「担当」「工程間の依存関係（先行→後続）」の4つだけ。

現状（`reference_現状進捗画面.png`）の問題:

- 同じタスク名が **ガント／進捗スライダー／削除リンクの一覧** の3か所に重複表示され、どこを見ればよいか不明
- ガントが小さく固定幅で、日付軸（9/21・9/7・9/14…）が不整合かつ読めない
- 進捗スライダーがガント行と対応していない位置に独立して並ぶ
- 追加フォームの入力欄が無ラベル（プレースホルダのみ）、日付欄が2つ並ぶだけで開始／終了が不明
- 大工程／中工程の階層がない（フラットなタスク列）
- 今日の位置・工程間の依存関係が表現されていない
- 行操作が「削除」リンクのみ、しかも本文と離れた別リストにある

改修方針（採用案 = **5c：ガント＋詳細パネルの2ペイン**）:

1. **左＝WBS列＋ガント（主役）／右＝選択工程の詳細パネル**
2. 階層は **大工程 → 中工程 の2階層**。大工程のバーと期間は**中工程から自動集計**（直接編集しない）
3. **バーの色 = 主担当**。担当チップのクリックで担当別にハイライト（他はディム）
4. **依存関係（先行→後続）をガント上のコネクタ線で可視化**。先行工程を動かすと後続が自動追従
5. 進捗率・完了・締切・遅延はUIから排除。状態表示は「担当」と「期間」のみ
6. 期間は**稼働日（土日除外）**で表示
7. 幅の優先順位はガント > 詳細パネル > 章ナビ。**章ナビは56pxのアイコンレール、詳細パネルは46pxストリップに収納可能**
8. 章ナビ・配色・タイポは **3a（5. システム要件）／4b（4. KPI）と共通**

## About the Design Files

このバンドルのHTMLは **HTMLで作成したデザインリファレンス（プロトタイプ）** であり、そのまま本番投入するコードではない。意図した見た目と挙動を示すものなので、**対象コードベースの既存環境（React / Vue / Rails など）と既存のパターン・ライブラリで作り直す** ことがタスク。環境が未整備なら適切なフレームワークを選定して実装してよい。

HTML内のインラインスタイルや独自ランタイム（`support.js`）はプレビュー用の仕組みで、実装で真似する必要はない。値（色・サイズ・余白・コピー）と挙動だけを取り出すこと。

ファイル:
- `進捗画面 5c 高精度デザイン.dc.html` — **実装対象**（高精度）。ブラウザで直接開けて操作できる
- `要件画面UXワイヤーフレーム.dc.html` — 検討過程の低精度ワイヤー。**ターン5（5a / 5b / 5c）がこの進捗画面の検討**で、5c が採用案（5a・5b は不採用だが「なぜ2ペイン＋依存関係にしたか」の背景）
- `参考_要件画面 3a 高精度デザイン.dc.html` / `参考_KPI画面 4b 高精度デザイン.dc.html` — 同システムの別章。**共通トークン・章ナビ・2ペイン構成の参照元**
- `reference_現状進捗画面.png` — 改修前スクリーンショット
- `support.js` — プレビュー用ランタイム（実装不要）

## Fidelity

**High-fidelity（hifi）**。`進捗画面 5c 高精度デザイン.dc.html` が最終の配色・タイポグラフィ・余白・状態遷移を持つ。ただし **既存プロダクトのデザインシステムが優先**。担当色は後述のパレットを既存のカテゴリカラーにマップしてよい（色数と彩度の水準は維持すること）。

## Interactions & Behavior

1. **行選択** — WBS行またはバーのクリックで選択。詳細パネルが切り替わり、依存コネクタの当該チェーンが `#8f3a22` にハイライト。バーに `box-shadow` のリング
2. **折りたたみ** — 大工程のキャレットで中工程を開閉（行選択とは分離）。開閉状態はユーザー単位で永続化
3. **スケール切替** — 日（21日窓）／週（10週）／月（3か月）。バー位置は窓に応じて再計算し、窓外はクランプ。`今日へ` は日スケールに切り替えて今日位置へスクロール
4. **担当フィルタ** — 担当チップのクリックでその担当のみ強調（他は `opacity:.22`）、再クリックで解除。**行は消さない**（構造が崩れて見えないため）
5. **バーのドラッグ** — 本体ドラッグで期間を平行移動、左右端で伸縮。グリッド単位（日）にスナップ。**先行工程を動かすと後続工程も同じ日数だけ自動追従**（依存チェーンを再帰的にシフト、循環参照はガード）
6. **依存関係の設定** — 詳細パネルの「先行工程」から選択、またはバー端からのドラッグで接続（実装が重い場合はパネルからの選択のみで可）。**循環参照は禁止**（自身の後続チェーンに含まれる工程は先行候補から除外）
7. **大工程の自動集計** — 期間は子の最小開始〜最大終了。**大工程の期間は直接編集させない**。子が0件の大工程はバーを描画しない
8. **追加** — `＋ 大工程`（末尾に追加）／`中工程を追加`（選択中の大工程の末尾に、直前工程を先行工程として自動設定、開始日は直前工程の翌日）。追加後はその行を選択してインライン編集にフォーカス
9. **並べ替え・階層変更** — WBS行のドラッグ、`⋯` メニューの「上へ／下へ移動」「大工程を変更」。**並び順は提案書の掲載順**として保存
10. **インライン編集** — 工程名・日付・担当はクリックで編集（オートセーブ、`Esc` で取消）
11. **ペインの折りたたみ** — 章ナビ（`☰`）と詳細パネル（`詳細を閉じる ›`）は独立に折りたためる。**ガントのクライアント幅が400pxを下回る環境では、初期表示でこの2つを畳む**（プロトタイプでは章ナビが既定で折りたたみ）
12. **キーボード** — `↑↓` で行移動、`Enter` で編集、`⌥←→` で選択工程を1日ずつ移動
13. **扱わないもの** — 進捗率、完了フラグ、遅延判定、締切アラート、実績工数。これらのUIを足さないこと（この章は計画の定義のみ）
14. **エラー** — 保存失敗時は楽観更新をロールバックしトーストで通知。循環参照や大工程の期間矛盾は保存前にインラインで警告（文字 `#8f3a22` / 背景 `#fbeae5` / 枠 `#efcbc0`）

## State Management

サーバ側データ:
- `Phase`（大工程）: `{ id, chapterId, name, order }`
- `Task`（中工程）: `{ id, phaseId, name, order, startDate, endDate, ownerId, subOwnerId, predecessorId | null }`
  - **進捗率・ステータスのフィールドは持たない**
- `Member`: `{ id, name, color }` — **色はメンバーに紐づけて永続化**（担当が変わればバー色も変わる）

UI状態:
- `selectedId: string`（大工程 or 中工程）
- `collapsedPhaseIds: Set<string>`（永続化）
- `scale: 'day'|'week'|'month'`、`windowStart: date`
- `ownerFocus: memberId | null`（担当ハイライト）
- `showDependencies: boolean`（既定 true）
- `navCollapsed: boolean`（既定 true）、`panelCollapsed: boolean`（既定 false）
- `dragging: { taskId, mode:'move'|'resize-start'|'resize-end', deltaDays } | null`

派生値（計算で出す。保存しない）:
- 大工程の期間（子の min/max）、工程全体の期間と稼働日数、担当ごとの工程数、表示中の行リスト（折りたたみ反映）、バーの left/width、依存コネクタの座標

主な操作:
- `select(id)` / `toggleCollapse(phaseId)` / `setScale(s)` / `jumpToToday()`
- `setOwnerFocus(memberId | null)` / `toggleDependencies()`
- `moveTask(taskId, deltaDays)` → 当該工程＋**依存チェーンの後続を再帰的にシフト**（1リクエストで一括更新）
- `resizeTask(taskId, {startDate | endDate})` → 終了日を伸ばした場合も後続をシフト
- `setPredecessor(taskId, predecessorId | null)` → 循環参照チェック
- `addPhase()` / `addTask(phaseId)` / `reorder(id, newOrder | newPhaseId)` / `remove(id)`
- `updateTask(taskId, field, value)`（オートセーブ、デバウンス 600ms）

データ取得: 章表示時に大工程・中工程・メンバーを1回で取得（数十件規模）。日付・担当・依存の更新はPATCH、連鎖シフトはサーバ側で計算して影響行をまとめて返すのが望ましい。
